<tr><td style="padding:14px 20px;"><div style="text-align:center;font-size:1.6em;">¿Qué es un SISTEMA?</div>
<p>Es una <u>colección de elementos y sus relaciones</u> definidas para conseguir un determinado <u>fin</u>. Dichos elementos pueden ser <u>reales o abstractos</u>.</p>
<p>Todos los sistemas tienen:</p>
<ul>
<li><u>Composición</u> (elementos)</li>
<li><u>Estructura</u> (relaciones entre elementos)</li>
<li><u>Ambiente</u> (influencia de factores externos)</li>
</ul>

<tr><td style="padding:14px 20px;"><div style="text-align:center;font-size:1.6em;">¿Qué es un Modelo?</div>
<p style="text-align:justify;line-height:1.8;">Un MODELO es una <u>representación abstracta de un sistema</u>. Esta representación puede ser conceptual, gráfica, física, matemática, etc.</p>

<p style="text-align:justify;line-height:1.8;">Es la ciencia y arte de <u>diseñar un modelo</u> de un sistema y <u>experimentar con este modelo</u> con el propósito de <u>entender el comportamiento real</u> del sistema modelado.</p>

<p>La Simulación de Modelos puede ser utilizada a 4 niveles:</p>
<ul>
<li>Para definir un sistema o proceso</li>
<li>Como herramienta de análisis y toma de decisiones</li>
<li>Como asesoramiento para evaluar o sintetizar soluciones</li>
<li>Como predictor para planear futuros desarrollos</li>

<!-- D9 a D14: El Proceso de Simulación -->
<table width="100%" style="border-collapse:collapse;border:1px solid #000;border-left:10px solid #35ace8;font-family:'Candara','Segoe UI',Calibri,sans-serif;background:#efefef;">
<tr><td style="padding:14px 20px;"><div style="text-align:center;font-size:1.6em;"><u>El Proceso de Simulación</u></div>

<div style="background:#35ace8;color:#fff;border-radius:6px;padding:6px 10px;font-size:1.2em;margin-top:12px;">1. Formulación del problema</div>
<ul style="margin:4px 0;"><li>Incluye determinación de objetivos.</li></ul>

<div style="background:#35ace8;color:#fff;border-radius:6px;padding:6px 10px;font-size:1.2em;margin-top:12px;">2. Construcción del modelo</div>
<ul style="margin:4px 0;text-align:justify;"><li>Consiste en la abstracción del problema en relaciones lógico-matemáticas que estén de acuerdo con su formulación.</li></ul>

<div style="background:#35ace8;color:#fff;border-radius:6px;padding:6px 10px;font-size:1.2em;margin-top:12px;">3. Toma de datos</div>
<ul style="margin:4px 0;"><li>Identificación, especificación y colección de datos</li></ul>

<div style="background:#35ace8;color:#fff;border-radius:6px;padding:6px 10px;font-size:1.2em;margin-top:12px;">4. Traslado del Modelo</div>
<ul style="margin:4px 0;"><li>Preparación del modelo para pasarlo al computador</li></ul>

<div style="background:#35ace8;color:#fff;border-radius:6px;padding:6px 10px;font-size:1.2em;margin-top:12px;">5. Verificación</div>
<p style="margin:4px 0 0 1em;font-size:0.95em;">•Proceso para comprobar que el computador hace lo que quiero.<br>
•Técnicas a utilizar:<br>
a) Escribir y depurar los programas en módulos y subprogramas<br>
b) Correr la simulación con distintos conjuntos de parámetros de entrada, y comprobar que la salida es razonable<br>
c) Correr el modelo con hipótesis simplificadas para las que el modelo tenga solución analítica</p>

<div style="background:#35ace8;color:#fff;border-radius:6px;padding:6px 10px;font-size:1.2em;margin-top:12px;">6. Validación</div>
<ul style="margin:4px 0;">
<li>Proceso que establece la relación entre el modelo y el sistema real.</li>
<li>Pasos para crear un modelo válido:</li>
</ul>
<ol style="margin:0;">
<li>Sugerir un modelo lógico.</li>
<li>Validar empíricamente las suposiciones del modelo.</li>
<li>Evaluar en qué medida los datos de salida son representativos.</li>
</ol>

<div style="background:#35ace8;color:#fff;border-radius:6px;padding:6px 10px;font-size:1.2em;margin-top:12px;">7. Planeamiento estratégico y táctico</div>
<ul style="margin:4px 0;"><li>Proceso que establece condiciones experimentales de uso del modelo.</li></ul>

<div style="background:#35ace8;color:#fff;border-radius:6px;padding:6px 10px;font-size:1.2em;margin-top:12px;">8. Experimentación</div>
<ul style="margin:4px 0;"><li>Ejecución del modelo y obtención de resultados.</li></ul>

<div style="background:#35ace8;color:#fff;border-radius:6px;padding:6px 10px;font-size:1.2em;margin-top:12px;">9. Análisis de resultados</div>
<ul style="margin:4px 0;"><li>Análisis de las salidas del modelo para sacar conclusiones y formular recomendaciones.</li></ul>

<div style="background:#35ace8;color:#fff;border-radius:6px;padding:6px 10px;font-size:1.2em;margin-top:12px;">10. Implementación y documentación</div>
<ul style="margin:4px 0;"><li>Proceso de poner en práctica las decisiones y documentar el modelo y su operación.</li></ul>

<li>Se pueden comparar distintas alternativas de diseño (o de formas de operar de un sistema), para ver cual se comporta mejor</li>
<li>Permite estudiar en poco tiempo la evolución de un sistema en un periodo largo de tiempo y al revés</li>
<li>Se puede utilizar para validar un modelo analítico</li>
</ul></td>

## Parte 3 · Pardo — "Introducción a la simulación" (resumen de estudio)

> **Nota:** este apartado es un **resumen propio** del capítulo 1 del libro *Simulación. Aplicaciones prácticas en la empresa* (págs. 1–5), no una transcripción. Para el texto completo consultá el libro.

<table width="100%" style="border-collapse:collapse;font-family:Arial,Helvetica,sans-serif;font-size:0.92em;">
<tr><td style="background:#35ace8;color:#fff;padding:4px 8px;"><b>1.1 ¿Qué se entiende por simulación?</b></td></tr>
<tr><td style="border:1px solid #35ace8;padding:8px;line-height:1.6;">
<ul>
<li><b>Origen:</b> el uso moderno del término se sitúa hacia 1949, con el método de Montecarlo (Von Neumann y Ulam).</li>
<li><b>Definición adoptada (Shannon, 1975):</b> simular es diseñar un modelo de un sistema real y experimentar con él para aprender su comportamiento o evaluar estrategias de funcionamiento.</li>
<li><b>Modelo (según Minsky):</b> X es modelo de Y para un observador Z si Z puede usar X para responder preguntas sobre Y. Es una forma simplificada del sistema.</li>
<li><b>Sistema:</b> conjunto de objetos o ideas interrelacionados que funcionan como unidad para lograr un fin.</li>
<li><b>Dos vías para obtener modelos matemáticos:</b>
  <ul>
  <li><i>Análisis teórico (método deductivo):</i> se estudian los fenómenos, se aplican leyes físicas u otras y se llega a ecuaciones del sistema.</li>
  <li><i>Análisis experimental:</i> se construye el modelo a partir de mediciones sobre el sistema y luego se experimenta con él. Esa experimentación es la "simulación del modelo".</li>
  </ul></li>
<li><b>Idea central:</b> un modelo de simulación no se "resuelve", se "hace funcionar". Lo que devuelve no es una solución óptima sino una descripción del comportamiento del sistema bajo las condiciones que fija el experimentador.</li>
</ul>
</td></tr>
<tr><td style="background:#35ace8;color:#fff;padding:4px 8px;"><b>1.2 Ventajas e inconvenientes del uso de la simulación</b></td></tr>
<tr><td style="border:1px solid #35ace8;padding:8px;line-height:1.6;">
<p style="margin:0 0 4px;"><b>Cuándo conviene simular</b> (situaciones señaladas por Shannon, 1975):</p>
<table style="border-collapse:collapse;width:100%;">
<tr style="background:#cfe0f3;"><td style="padding:3px;width:5%;">(a)</td><td style="padding:3px;">No hay formulación matemática del sistema, o no hay métodos analíticos para resolverla. <i>Ej.: dimensionar los servicios de un aeropuerto.</i></td></tr>
<tr style="background:#e8eef8;"><td style="padding:3px;">(b)</td><td style="padding:3px;">Hay modelo y métodos, pero son tan laboriosos que simular es más simple y barato. <i>Ej.: asignar muchas tareas a máquinas o personas.</i></td></tr>
<tr style="background:#cfe0f3;"><td style="padding:3px;">(c)</td><td style="padding:3px;">Se quiere experimentar antes de construir el sistema. <i>Ej.: simulador de vuelo para entrenar tripulaciones.</i></td></tr>
<tr style="background:#e8eef8;"><td style="padding:3px;">(d)</td><td style="padding:3px;">Es imposible experimentar sobre el sistema real. <i>Ej.: el rescate del Apolo 13, preparado gracias a simulaciones previas de la NASA.</i></td></tr>
<tr style="background:#cfe0f3;"><td style="padding:3px;">(e)</td><td style="padding:3px;">Experimentar es posible, pero razones éticas lo impiden. <i>Ej.: sistemas biológicos humanos.</i></td></tr>
<tr style="background:#e8eef8;"><td style="padding:3px;">(f)</td><td style="padding:3px;">El sistema evoluciona muy lentamente y la simulación comprime la escala de tiempo. <i>Ej.: políticas de tala forestal y propagación de la enfermedad Armillaria (Morgan, 1984).</i></td></tr>
<tr style="background:#cfe0f3;"><td style="padding:3px;">(g)</td><td style="padding:3px;">Permite estudiar sistemas dinámicos en tiempo real.</td></tr>
</table>
<p style="margin:10px 0 4px;"><b>Inconvenientes:</b></p>
<table style="border-collapse:collapse;width:100%;">
<tr style="background:#efb8b4;"><td style="padding:3px;width:5%;">(a)</td><td style="padding:3px;">Construir el modelo puede ser complejo, caro y lento. Forrester (1961) habla de 8 a 10 años para un modelo socioeconómico.</td></tr>
<tr style="background:#f6d6d3;"><td style="padding:3px;">(b)</td><td style="padding:3px;">Omitir elementos o relaciones aparentemente menores puede falsear los resultados, sobre todo en sistemas grandes y en previsiones. <i>Ej.: los modelos del Club de Roma.</i></td></tr>
<tr style="background:#efb8b4;"><td style="padding:3px;">(c)</td><td style="padding:3px;">Es difícil, si no imposible, conocer el grado de imprecisión de los resultados.</td></tr>
</table>
</td></tr>
</table>

## Parte 4 · Coss Bu — "Introducción" (resumen de estudio)

> **Nota:** este apartado es un **resumen propio** del capítulo 1 de *Simulación: un enfoque práctico* (R. Coss Bu, págs. 11–18), no una transcripción. Para el texto completo consultá el libro.

<table width="100%" style="border-collapse:collapse;font-family:Arial,Helvetica,sans-serif;font-size:0.92em;">
<tr><td style="background:#1f3864;color:#fff;padding:4px 8px;"><b>Contexto</b></td></tr>
<tr><td style="border:1px solid #1f3864;padding:8px;line-height:1.6;">Con la computadora, la simulación pasó a ser una de las principales herramientas para analizar sistemas complejos. El uso moderno del término se remonta a la década de 1940 (Von Neumann y Ulam, proyecto Monte Carlo). El libro se enfoca en aplicaciones a economía, administración e investigación de operaciones, y sobre todo en <b>sistemas dinámicos discretos</b>.</td></tr>

<tr><td style="background:#1f3864;color:#fff;padding:4px 8px;"><b>1.1 Definición de simulación</b></td></tr>
<tr><td style="border:1px solid #1f3864;padding:8px;line-height:1.6;">
<table style="border-collapse:collapse;width:100%;">
<tr style="background:#cfe0f3;"><td style="padding:3px;width:25%;"><b>T. H. Naylor</b></td><td style="padding:3px;">Técnica numérica para hacer experimentos en computadora digital con relaciones matemáticas y lógicas que describen un sistema complejo a lo largo del tiempo. Es una definición amplia: abarca desde una maqueta hasta un programa sofisticado.</td></tr>
<tr style="background:#e8eef8;"><td style="padding:3px;"><b>Maisel y Gnugnoli</b></td><td style="padding:3px;">Versión más estricta: experimentos en computadora con modelos matemáticos y lógicos de sistemas de negocios, económicos, sociales, biológicos, físicos o químicos.</td></tr>
<tr style="background:#cfe0f3;"><td style="padding:3px;"><b>R. E. Shannon</b></td><td style="padding:3px;">Diseñar un modelo computarizado de un sistema y experimentar con él para entender su comportamiento o evaluar estrategias de operación.</td></tr>
</table>
</td></tr>

<tr><td style="background:#1f3864;color:#fff;padding:4px 8px;"><b>1.2 Etapas de un estudio de simulación</b></td></tr>
<tr><td style="border:1px solid #1f3864;padding:8px;line-height:1.6;">
<ol>
<li><b>Definición del sistema:</b> análisis preliminar, interacciones, restricciones, variables y medidas de efectividad.</li>
<li><b>Formulación del modelo:</b> variables, relaciones lógicas y diagramas de flujo.</li>
<li><b>Colección de datos:</b> definir qué datos se necesitan. Fuentes: registros contables, órdenes, expertos o experimentación.</li>
<li><b>Implementación en computadora:</b> lenguaje general (Fortran, Basic, Algol) o paquete de simulación (GPSS, Simula, Simscript).</li>
<li><b>Validación:</b> opinión de expertos, predicción de datos históricos, predicción del futuro, falla con datos que hacen fallar al sistema real, y confianza del usuario.</li>
<li><b>Experimentación:</b> una vez validado el modelo; genera datos y análisis de sensibilidad.</li>
<li><b>Interpretación:</b> apoya decisiones semi-estructuradas. La computadora no decide, informa.</li>
<li><b>Documentación:</b> técnica (para el área de procesamiento de datos) y manual del usuario.</li>
</ol>
</td></tr>

<tr><td style="background:#1f3864;color:#fff;padding:4px 8px;"><b>1.3 Factores a considerar en el desarrollo del modelo</b></td></tr>
<tr><td style="border:1px solid #1f3864;padding:8px;line-height:1.6;">
<ul>
<li><b>1.3.1 Variables aleatorias no uniformes:</b> en modelos estocásticos se generan a partir de números uniformes y una transformación (normal, exponencial, Poisson, Erlang, binomial, gamma, beta, F, t, etc.).</li>
<li><b>1.3.2 Lenguajes de programación:</b> desarrollar software propio o comprar un paquete de propósito especial (GPSS, GASP, etc.) evaluándolo antes.</li>
<li><b>1.3.3 Condiciones iniciales:</b> los estados transitorios del arranque distorsionan el estado estable. Hay tres alternativas: corrida larga, descartar el tramo inicial o simulación regenerativa. El autor considera que la regenerativa es la de menos desventajas.</li>
<li><b>1.3.4 Tamaño de la muestra (número de corridas):</b> equilibrar la precisión con el costo. Se determina antes de operar el modelo o durante la operación, mediante intervalos de confianza.</li>
<li><b>1.3.5 Diseño de experimentos:</b> comparar medias y varianzas de alternativas (factor simple), medir el efecto de variables (ANOVA, regresión) y buscar óptimos con heurísticas (por ejemplo, Hooke y Jeeves).</li>
</ul>
</td></tr>

<tr><td style="background:#1f3864;color:#fff;padding:4px 8px;"><b>1.4 Ventajas y desventajas</b> (ventajas según T. H. Naylor)</td></tr>
<tr><td style="border:1px solid #1f3864;padding:8px;line-height:1.6;">
<table style="border-collapse:collapse;width:100%;">
<tr><th style="background:#a9d18e;padding:3px;width:60%;text-align:left;">Ventajas</th><th style="background:#efb8b4;padding:3px;text-align:left;">Desventajas</th></tr>
<tr><td style="vertical-align:top;padding:3px;">
• Estudiar el efecto de cambios internos y externos.<br>
• Entender mejor el sistema y sugerir mejoras.<br>
• Uso pedagógico (estadística, análisis teórico).<br>
• Detectar las variables clave y sus interrelaciones.<br>
• Experimentar con situaciones nuevas o poco conocidas.<br>
• Entrenar personal (por ejemplo, con juegos de negocios).<br>
• Anticipar cuellos de botella al introducir cambios.</td>
<td style="vertical-align:top;padding:3px;">
• Requiere equipo de cómputo y recursos humanos costosos.<br>
• Lleva bastante tiempo desarrollarlo y perfeccionarlo.<br>
• La alta dirección puede no entender la técnica, lo que dificulta "vender" la idea.</td></tr>
</table>
</td></tr>

<tr><td style="background:#1f3864;color:#fff;padding:4px 8px;"><b>1.5 Ejemplos de usos</b></td></tr>
<tr><td style="border:1px solid #1f3864;padding:8px;line-height:1.6;">
<ul>
<li><b>Sistemas de colas:</b> llegadas en grupo, abandono, rechazo si la cola es larga.</li>
<li><b>Inventarios</b> con parámetros estocásticos (tiempo de entrega, demanda, costos).</li>
<li><b>Proyectos de inversión</b> con incertidumbre en flujos, tasas o inflación.</li>
<li><b>Sistemas económicos:</b> efecto de devaluación, IVA, etc. sobre variables macroeconómicas.</li>
<li><b>Estados financieros:</b> evaluar estrategias de crecimiento y diversificación a corto, mediano y largo plazo.</li>
</ul>
